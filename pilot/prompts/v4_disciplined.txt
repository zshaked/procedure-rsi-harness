Disciplined selection. Oracle budget: 15 questions. Write procedure.py from the histories and iterate with harness.py until you have a procedure you believe in. procedure.py must also define decide(request, tools) -> (response_dict, branch) where branch is a short string naming the rule that decided the outcome (e.g. "auth_level", "qty_mismatch", "confirm_pending"); respond() returns decide()[0]. Then plan ALL your questions once, by this protocol, before asking any:

S1. Run decide() on all 200 requests (25 histories + 175 unlabeled). For each branch, count the history cases it decided and the unlabeled cases it decided.
S2. Unsupported branches: decided 0 or 1 history cases. Order them by unlabeled count, descending. For each, choose one unlabeled case it decides, preferring a case where a different plausible rule would give a different outcome.
S3. Parameter edges: for every numeric threshold or tolerance in the procedure, and for every convention you adopted without history evidence (for example: settled vs settled-plus-pending; what to do with no date; how a non-business-day date is handled; what the as-of-assumed flag means), choose the unlabeled case whose relevant value is closest to the threshold on each side (two cases per threshold; one case per convention). Order these by the unlabeled count of the branch they belong to, descending.
S4. Do NOT plan a question about a branch that decided two or more history cases with full-field agreement, unless a history case disagrees with your procedure on it.
S5. The plan is S2 then S3, in that order, truncated to 15. If it has fewer than 15, stop there; unused budget is allowed. Write the plan (branch table, chosen cases, reason for each) to NOTES.md before asking anything, then ask in plan order. Do not re-plan. You may change the procedure after any answer.

One rule for using answers, followed exactly:
R2. Before changing a rule that at least two history cases support (two or more operator replies consistent with it at the field level), you need two oracle answers on two different cases that both contradict it. One contradicting answer is not enough: log it and ask a second case on the same rule before changing anything. A rule supported by zero or one history case may be changed on a single answer.
